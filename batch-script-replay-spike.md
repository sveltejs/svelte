# Per-batch script replay: bounded spike

## Starting point and scope

Inspected on 2026-11-16. The clean checkout was `0f5e2f8988c2bfa3eeae0a32c3b13496e61bba7e` on `batch-views-script-replay-plan`. Its only difference from `06910d5b2bd547e2bba7b0ffe5669dbf5f7b0a48` was `batch-script-replay-plan.md` (two plan commits). No handoff implementation was merged, reset to, or cherry-picked. Recovered test provenance and the untouched-runtime results are in [batch-script-replay-baseline.md](batch-script-replay-baseline.md).

This is a deliberately opt-in client experiment, not a replacement for all async lowering. The existing/default compiler and SSR retain their contract. The compiler option is `experimental: { async: true, scriptReplay: true }`. Unsupported client syntax must be rejected, not silently split between replay and shared continuation assignments.

## Phase-0 decisions

| Question                     | Decision for this spike                                                                                                                                                                                                                                                                       |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Replay region                | Existing analysis-defined async suffix only. Prefix state/props/functions belong to the stable shell. This is not a general decision about whole-script semantics.                                                                                                                            |
| Storage                      | One versioned, immutable selection/progress snapshot with an undoable `null` baseline; equality-preserving projections for readiness/bindings. Async results and initialization publication have async-result provenance, not ordinary-input provenance.                                      |
| Producer identity            | One effect per logical producer site per initializer, shared across views; each execution deliberately selects that view's factory environment. No `async_derived` one-shot creation path, and no producer closure captured from another attempt.                                             |
| Attempt identity             | Initializer + canonical batch + generation. Canonical batch equality alone never validates a continuation. A run token also rejects replaced work within an attempt.                                                                                                                          |
| Admission                    | An explicit preserved scheduler is revalidated on branch adoption, including when its own dependency list is empty. Admission deduplicates; publishing a checkpoint is not itself invalidation.                                                                                               |
| Rebase                       | A changed completed prefix invalidates/restarts the unfinished suffix conservatively. Pending local producer replacement must not publish a mixture of old snapshots and new derived values.                                                                                                  |
| Checkpoints                  | Preserve analysis's coarse continuation groups. A group is ready only after all its declarations have published coherently.                                                                                                                                                                   |
| Outcome                      | Pending, successful, failed (including the original thrown value), and cancelled are distinct. Failure is not a boolean readiness that stays false forever.                                                                                                                                   |
| Merge                        | Select one whole incoming attempt/generation, retire losing work promptly, and retain stable logical producer identity and deferred render work. Never combine partial lexical environments.                                                                                                  |
| Sealing                      | Only a successful final checkpoint actually committed in a still-selected real branch establishes the component. Early pending-boundary commits and fork completion do not seal.                                                                                                              |
| Existing forks after sealing | Preserve established prefix state, template/DOM identity, and ordinary snapshots. Existing private errors remain errors unless their expression is genuinely superseded. An old successful fork may update reactive producer results, but must not reinstall or reset the component lifetime. |
| Cancellation                 | Retire tokens before abort callbacks, settle accounting exactly once without waiting for user promises, suppress late publication and later framework stages. JavaScript external side effects/finally cannot be undone.                                                                      |
| Failed commit                | Commit is not a retry. An already-failed fork must report its current cached error; repeated commit must not silently succeed. Commit requested while pending must receive a later rejection, not leak it into an unrelated microtask.                                                        |
| Presentation                 | Install effects once; gate before reading bindings or evaluating selectors. A previously created content branch is skipped in an unready view and revalidated, not reconstructed, in a ready view.                                                                                            |

## Compiler contract

`script_replay(factory, kinds, checkpoints)` creates the stable initializer shell and exposes `ready` sources. The factory receives stable per-site binding handles and creates a fresh lexical environment for each admitted attempt. Its per-site functions are classified as `async`, `derived`, or `local`; checkpoints retain the original group indices.

Only one root await in an identifier async-derived declaration is supported. The lowering removes that await into the runtime's validated suspension boundary. Nested/inline awaits, mutable suffix state/overrides, destructuring, escaping suffix closures, context/store/lifecycle registration, template awaits/declarations, and blocked directives are not implicitly supported. Binding storage metadata is separate from `binding.blocker`. Server lowering keeps the existing default strategy.

## Verification and obligations

Results below will distinguish observed behavior from intended contracts. A passing initial render is not evidence for sealing, existing-fork adoption, supersession, or stable effect identity. The recovered historical fixtures keep their correctness assertions; exact speculative execution counts are classified separately, never silently weakened.

The bounded phase-1 kernel and phase-2 client lowering are implemented. The focused cases below pass on generated code as well as hand-written inputs, including updates after publication. This is not a claim that all phase-1/P0 interleavings are proved, that phase 3 is production-complete, or that the old coordination machinery can already be deleted.

### Counterexamples found while building the spike

- **A new version is not an inert normalization.** Rewriting an old successful fork's selection snapshot at commit to substitute established locals changed its source version, invalidated cached producer records, and stranded commit on requests that should not have restarted. Keep the selection/version that the work actually observed; publish lifetime-local selection separately at sealing.
- **Normalizing displayed locals does not normalize closures.** In `a -> snapshot = a -> b = await load(a + snapshot)`, an old fork's producer closure can keep its private `snapshot` even when the template shows the established snapshot. Supported factory-stage reads of locals therefore go through stable binding projections as well. Lexical variables are attempt-local assignment destinations, not a hidden second storage path. A producer that actually depends on a changed local may need a successful revalidation; unrelated producer sites must not be restarted by positional/environment heuristics.
- **Cached failure can be hidden behind unrelated pending work.** Checking errors only after `Promise.all(pending)` leaves an already-failed commit waiting forever for a never-settling sibling initializer. Error inspection must precede the wait. Skipped/unselected initializers also must not keep commit pending.
- **A sealed initializer still has per-view failures.** Later producer success and failure must both belong to the executing batch, not mutate the original attempt's global outcome. New forks need private update-outcome storage even though the initializer factory is not replayed.
- **Initial `settled()` is not an adequate fixture barrier here.** The compiler-chain fixture's immediate post-mount `settled()` returned before its output existed with both the base lowering and replay. An initial `tick()` followed by `settled()` is used to drain initial work; post-update assertions still use `settled()` and check retained nodes/state/snapshots. This is recorded as a baseline timing limitation, not credited as a replay fix.

- **A successful sibling is not a successful replacement.** After sealing, independent producer sites may run concurrently. A single attempt-wide last-error field lets `b` succeeding clear `a`'s failure. Outcomes therefore retain errors by producer site; only a current successful execution of that site can replace its error.
- **Handled-error preparation must not freeze a stale callback.** Calling the existing boundary error path while a fork still waits on another initializer skips the failed branch and captures an unconditional commit callback. The spike uses a read-only boundary-capability check for fatal preflight, leaves handled errors revalidatable while waiting, and synchronously checks the final selected outcomes immediately before applying the fork.
- **Nonreactive does not mean unvalidated during initialization.** A plain snapshot can read a prefix source that no async producer reads. Untracking its evaluation loses that prefix's provenance while later stages await. Local-site dependencies must be tracked until publication, then dropped; ordinary locals must not turn into reactive deriveds after sealing.
- **Established locals cannot erase an already-cached private failure.** For `a -> snapshot -> b(a + snapshot)`, publishing an unrelated real attempt's lifetime locals must not change a failed fork's inputs and retry `b`. The failed private snapshot stays private; successful adoption and genuinely superseding inputs are separate operations.

These findings change the implementation/proof obligations; they are not reasons to relax cached-error identity, cancellation, or established-lifetime assertions.

### Complexity and generalization boundary

The spike uses stable producer effects plus a per-batch initializer map, an immutable selection snapshot, a separately published lifetime-local source, equality-preserving projections, and per-run cancellation/accounting. Attempt object identity is the generation token. There is no first-value owner or transfer of one shared script continuation. Supported suspension is the one root await removed into the runtime's validated completion boundary.

The default promise-blocker runner remains because most of the language is deliberately not converted. This is a temporary dual contract behind an explicit option, not a claim that the final design is smaller. Whole-prefix replay, mutable suffix state/overrides, arbitrary awaits, classes/destructuring/escaping closures, stores/context/lifecycle registration, nested component/each/key readiness, directives/attachments/actions, and template async declarations remain outside this spike. Full mixed-mode cleanup and reentrant abort/teardown ordering still need adversarial coverage; no general suspension protocol was retrofitted into the old runner.

Fork commit in the spike conservatively waits for selected replay work before making its input writes real, so that a late unhandled rejection reaches the commit waiter without partially publishing. This changes the publication timing of forks that introduce a pending boundary, compared with allowing that pending branch to become visible immediately. Preserving the general pending-boundary commit contract while retaining atomic error preflight is a phase-3 obligation, not solved merely by passing the pending-rejection test.

Narrow generated hydration is covered, not arbitrary partial hydration. The full suite has not been run and no PR is being submitted. Historical default-runner failures remain runnable, unskipped, and unmodified.
